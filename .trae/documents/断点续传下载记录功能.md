# 断点续传：下载记录与未下载续传功能实现计划

## 一、概述

为 IMA 下载工具新增「下载记录持久化 + 任务级断点续传」能力：

- 下载过程中把每个文件的 `已完成 / 失败` 状态写入 `chrome.storage.local`。
- 中断、关闭插件窗口、Service Worker 被回收后，再次打开仍然能识别哪些文件已下载、哪些未下载。
- 弹窗文件列表直接展示 `已下载 / 未下载 / 失败` 状态。
- 提供「全选未下载」按钮，一键勾选所有未完成（未下载 + 失败）的文件，点击「继续下载」只下载这些文件。

已确认的两个决策：

1. **任务级续传**（按文件粒度，跳过已下载文件），不做 HTTP Range 字节级续传。
2. **失败文件归入「未下载」**，可被「全选未下载」勾选并重试。

## 二、当前状态分析

现有下载流程（[background.js](file:///f:/Other_utils/sea_ima_tool/background.js)）：

- `batchDownload(headers, files, outputDir, concurrency)`（[L1074-L1179](file:///f:/Other_utils/sea_ima_tool/background.js#L1074-L1179)）：分批并发调用 `downloadFile()`，成功 `completed++`、失败 `failed++`，但**不持久化任何文件状态**。
- `downloadFile()` 内部通过 `downloadViaOffscreen()` 写入所选文件夹或回退 `chrome.downloads`。
- 扫描结果已缓存于 `scan_cache_${knowledgeBaseId}`（`chrome.storage.local`）。
- 弹窗的文件树与勾选逻辑在 [popup.js](file:///f:/Other_utils/sea_ima_tool/popup.js)：`buildFileTree()` 以 `{ ...file, index, checked: true }` 默认全选（[L446](file:///f:/Other_utils/sea_ima_tool/popup.js#L446)），`renderTreeNode()` 渲染文件行时硬编码 `checked`（[L534](file:///f:/Other_utils/sea_ima_tool/popup.js#L534)），文件夹勾选框硬编码 `checked`（[L473-L478](file:///f:/Other_utils/sea_ima_tool/popup.js#L473-L478)）。

因此当前中断/关闭后没有任何"哪些下过、哪些没下"的记忆，只能整批重下。

## 三、方案设计

### 1. 持久化存储结构（`chrome.storage.local`）

Key：`download_records_${knowledgeBaseId}`

Value：以 `mediaId` 为键的对象映射：

```js
{
  "<mediaId_a>": { status: "done",   title, doneAt, path },
  "<mediaId_b>": { status: "failed", title, failAt, error }
}
```

- `done`：已成功下载；`failed`：下载失败；**无记录 = 未下载**。
- 按知识库隔离，不同知识库互不影响。
- 单个条目极小，远低于 `chrome.storage.local` 配额（与现有 `scan_cache_` 同库，无额外权限）。`unlimitedStorage` 权限已具备。

### 2. 状态模型（前端）

每个扫描到的文件附加 `downloadStatus`：`"done" | "failed" | "pending"`（`pending` = 无记录/未下载）。

- 文件勾选框默认状态：`checked = (downloadStatus !== "done")`，即**未下载与失败默认勾选，已下载默认不勾选**。
- 文件夹勾选框默认：`checked = 该文件夹子树内存在至少一个未完成（非 done）文件`。

## 五、假设与决策

- 不实现单文件字节级（HTTP Range）续传，仅任务级跳过已完成文件。
- 「已下载」判定仅依赖应用内记录，不额外校验磁盘文件是否存在（避免过度设计）；若用户删除过本地文件或换机，可通过「全选」全量重下。
- 失败文件视为「未下载」，可重试；重试成功后记录覆盖为 `done`。
- 记录按知识库隔离，且不与扫描缓存绑定；清除扫描缓存不影响下载记录（如需重置，全量重新勾选并重下即可覆盖）。
- 既有「全选」勾选框语义保持不变：勾中 = 重下全部（含已下载）。

## 六、验证步骤

1. 加载扩展，选择知识库并扫描。
2. 默认勾选全部（首次全量）→ 开始下载，确认下载结束后 `chrome.storage.local` 中出现 `download_records_${kbId}`，且每个成功文件 `status:"done"`。
3. 关闭扩展窗口（甚至等 SW 回收后）重新打开 → 扫描 → 文件列表中已下载文件显示绿色「已下载」且默认不勾选，未下载/失败显示相应状态且默认勾选，摘要显示「已下载 X · 未下载 Y」。
4. 点「全选未下载」→ 仅勾选未下载 + 失败文件；点「继续下载」→ 只下载这些文件，不重复下载已完成文件。
5. 人为制造某个文件下载失败（如断网或错误链接）→ 该文件标记「失败」；后续「全选未下载」能重新包含并重试。
6. 回归：首次全量下载（无任何记录）时，行为与改造前一致（默认全选、按钮文案「开始下载」）。
