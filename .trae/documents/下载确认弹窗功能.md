# 下载确认弹窗：勾选文件夹后预览并只下载未下载文件

## 一、概述

在「下载记录 + 任务级续传」基础上，增加一个**下载前确认弹窗**：

- 用户在文件树中勾选文件夹（或文件）后点击「开始下载 / 继续下载」。
- 弹出**页面内模态框**，列出当前勾选的全部文件及其下载状态。
- 模态框内**未下载（含失败）的文件默认勾选**，已下载文件默认不勾选并标注「将跳过」。
- 用户确认后，仅下载模态框中勾选的文件。

已确认决策：

1. 弹窗形式：**页面内模态框**（遮罩层 + 对话框，复用现有 popup 页面，不新增文件）。
2. 文件范围：**当前勾选的文件**（勾选文件夹 = 勾选其下全部文件，经现有 `setNodeChecked` 已实现）。

## 二、当前状态分析

- 文件树勾选：`renderTreeNode()` 的文件夹 checkbox `change` 会调用 `setNodeChecked(folder, checked)`（[popup.js](file:///f:/Other_utils/sea_ima_tool/popup.js)），递归勾选/取消子树；文件 checkbox 直接改 `file.checked`。
- 已选收集：`getSelectedFiles()`（[L816-L822](file:///f:/Other_utils/sea_ima_tool/popup.js#L816-L822)）→ `collectCheckedFiles(fileTreeData)`，返回选中的 `scannedFiles[index]`，每个对象已带 `downloadStatus`（`done/failed/pending`）。
- 下载入口：`startDownload()`（[L886-L949](file:///f:/Other_utils/sea_ima_tool/popup.js#L886-L949)）目前**直接** `getSelectedFiles()` 后立即 `BATCH_DOWNLOAD`，没有预览/确认环节。
- 事件绑定集中在 `setupEventListeners()`。

因此本次改动核心：把 `startDownload` 拆成「收集→弹窗预览→确认→真正下载」，并新增模态框 UI。

## 三、具体改动

### 改动 1：[popup.html](file:///f:/Other_utils/sea_ima_tool/popup.html) — 新增模态框结构

在 `</div>`（`.container` 之后、`<script>` 之前，body 内）追加一个默认隐藏的模态框：

```html
<div id="download-confirm-modal" class="modal-overlay hidden">
  <div class="modal">
    <div class="modal-header">
      <h3>确认下载</h3>
      <button id="modal-close-btn" class="btn-small">×</button>
    </div>
    <div class="modal-summary">
      选中 <span id="modal-total">0</span> 个文件 ·
      已下载 <span id="modal-done">0</span>（将跳过）·
      将下载 <span id="modal-todo">0</span>
    </div>
    <div id="modal-file-list" class="modal-body"></div>
    <div class="modal-footer">
      <button id="modal-cancel-btn" class="btn btn-secondary">取消</button>
      <button id="modal-confirm-btn" class="btn btn-primary">确认下载</button>
    </div>
  </div>
</div>
```

### 改动 2：[popup.js](file:///f:/Other_utils/sea_ima_tool/popup.js) — 弹窗逻辑与下载入口拆分

1. 新增全局 `let pendingDownloadFiles = [];`（弹窗内待确认的文件快照）。

2. 拆分 `startDownload()`：
   - 保留函数名 `startDownload()`，职责改为：`getSelectedFiles()` → 空则 return → `openDownloadConfirm(files)`。
   - 将现有 `startDownload` 中「按钮置灰、重置暂停、显示进度、拼 outputDir、发送 `BATCH_DOWNLOAD`、处理结果」的主体逻辑抽取为新函数 `doDownload(files)`，参数改为显式传入文件数组（其余逻辑不变，去掉开头的 `selectedFiles = getSelectedFiles()`）。

3. 新增 `openDownloadConfirm(files)`：
   - `pendingDownloadFiles = files`。
   - 清空并渲染 `#modal-file-list`：每行 `[checkbox][文件名/路径][状态徽标][大小]`；`checkbox` 默认 `checked = (file.downloadStatus !== "done")`，`done` 行加弱化样式并显示「已下载」徽标、非 `done` 显示「未下载/失败」徽标。
   - 更新 `#modal-total / #modal-done / #modal-todo` 统计（done 数 / 非 done 数）。
   - 移除 `hidden` 显示模态框。

4. 新增 `closeDownloadConfirm()`：给模态框加回 `hidden`。

5. 新增 `confirmDownload()`：
   - 从弹窗内收集 `:checked` 的文件（`pendingDownloadFiles` 中对应项）→ 若为空则提示并 return。
   - `closeDownloadConfirm()` → `doDownload(checkedFiles)`。

6. 新增 `updateModalSummary()`：弹窗内 checkbox 变化时重算「将下载」数量并据此禁用/启用 `#modal-confirm-btn`（无勾选时禁用）。

7. 在 `setupEventListeners()` 中绑定：
   - `modal-close-btn` / `modal-cancel-btn` → `closeDownloadConfirm()`。
   - `modal-confirm-btn` → `confirmDownload()`。
   - 点击 `.modal-overlay` 背景（非 `.modal` 区域）→ `closeDownloadConfirm()`。

### 改动 3：[popup.css](file:///f:/Other_utils/sea_ima_tool/popup.css) — 模态框样式

追加：

- `.modal-overlay`：fixed 全屏遮罩，半透明背景，居中 flex，`z-index` 高于通知。
- `.modal`：白底圆角卡片，固定高度约 70vh，shadow-lg。
- `.modal-header / .modal-footer`：flex 布局。
- `.modal-body`：纵向滚动，`max-height` 自适应。
- `.modal-file-item`：每行 flex（复用 `.tree-file-status` 徽标）。`.modal-file-item.done` 加 `opacity` 弱化。
- 复用现有 CSS 变量（`--radius-lg`、`--shadow-lg`、`--border-color` 等）。

## 四、假设与决策

- 弹窗中「已下载」文件默认不勾选但**保留可手动勾选**能力（用户仍可选择重下），确认按钮在无勾选时禁用。
- 弹窗文件列表为**扁平列表**（不按目录树展示），按当前勾选顺序排列，简洁清晰。
- 「失败」文件与「未下载」一样默认勾选，可重试（延续上一功能决策）。
- `doDownload` 沿用现有 `outputDir` 计算与 `BATCH_DOWNLOAD` 消息，不改变后台逻辑。
- 下载完成后的进度/日志/通知逻辑保持不变。

## 五、验证步骤

1. 加载扩展 → 选知识库 → 扫描（部分文件已有「已下载」绿标）。
2. 勾选一个文件夹 → 点「开始下载/继续下载」→ 页面弹出「确认下载」模态框。
3. 模态框内：列表展示该文件夹下全部文件，未下载/失败默认勾选，已下载默认不勾选并弱化显示；顶部统计「已下载 X（将跳过）· 将下载 Y」正确。
4. 取消按钮 / 右上角 × / 点击遮罩 → 关闭模态框，不触发下载。
5. 确认下载 → 仅下载未下载（勾选）的文件，后台生成 `done` 记录；下载完成后重新扫描，相关文件变绿。
6. 全选后进入弹窗再手动逐个取消，确认按钮状态与「将下载」计数实时正确。
